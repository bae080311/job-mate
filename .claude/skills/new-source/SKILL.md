# 데이터 소스 추가

**이 프로젝트에서 반복되는 유일한 작업이고, 매번 같은 곳에서 틀린다.**
공공데이터 API 명세는 낡아 있는 경우가 많다 — 병역일터 명세의 날짜 예시는 2016년이다.
그래서 순서가 중요하다: **실측 먼저, 코드는 나중.**

## 0. 명세를 믿지 않는다

`data.go.kr` 의 "상세 기능정보"를 읽되 **그대로 코딩하지 않는다.** 읽는 목적은
엔드포인트와 인증 파라미터 이름을 아는 것까지다. 필드명·형식은 4단계에서 실측한다.

## 1. 키 확인

`.env` 에 환경변수가 있는지 먼저 본다. 없으면 여기서 멈추고 사용자에게 발급을 요청한다.
**키 없이 어댑터를 다 짜놓고 나중에 검증하는 건 하지 말 것** — 필드명이 틀려 있으면 전부 다시 짠다.

## 2. `fetch` 함수만 먼저 쓴다

`src/pipeline/collect.ts` 에 `fetchXxx(key, page)` 만 추가하고 `SOURCES` 에 등록한다.
`norm` 은 아직 만들지 말고 임시로 아무거나 넣어둔다. 목표는 `--probe` 를 돌리는 것뿐이다.

- HTTP 는 네이티브 `fetch` + `AbortSignal.timeout(20_000)` (axios 금지)
- 응답이 XML 이면 **멈추고 사용자와 상의할 것.** Node 에는 stdlib XML 파서가 없어서
  의존성이 하나 늘어난다. 그만한 가치가 있는 소스인지 먼저 판단한다

## 3. 실측

```bash
node src/pipeline/collect.ts --probe <소스명>
```

원본 1건이 그대로 찍힌다. 여기서 확인할 것:

- [ ] 실제 필드명 (명세와 다른 경우가 흔하다)
- [ ] **날짜 형식** — `2026-09-08`? `20260908`? `31/05/2016`(DD/MM/YYYY)? epoch?
- [ ] 학력 필드에 실제로 들어오는 문자열 (`"고등학교졸업 이상"` 등)
- [ ] 사업자등록번호가 있는가 (있으면 `mma_status` 확정 판정 가능, 없으면 `unknown`)
- [ ] 페이지네이션이 실제로 동작하는가 (`--pages 2` 로 확인)

## 4. `norm` 함수 작성

`Job` 타입을 채운다. 규칙:

- `hs_ok` 는 반드시 `hsOk(edu)` 를 통과시킨다. **직접 판정하지 말 것**
- `mma_status` 는 CLAUDE.md 1절을 따른다. 출처가 병무청 지정업체 포털이면 `designated`,
  상호명 추정이면 `unknown`. **상호명으로 `designated` 승격 절대 금지**
- 빈 문자열은 `nz()` 로 `null` 로 만든다
- `raw` 에 원본 객체를 그대로 넣는다 (파싱을 나중에 바꿔도 재수집 불필요)

## 5. 날짜 형식이 새로우면 `toDate` 확장

`toDate()` 에 패턴을 추가하고 **`selftest()` 에 케이스를 반드시 넣는다** —
정상 1개 + 잘못된 값 1개(`"2026-02-30"` 같은 것). `Date.UTC` 는 존재하지 않는 날짜를
조용히 다음 달로 굴리므로 되돌려 확인하는 검사가 필요하다.

## 6. 검증

```bash
npx tsc --noEmit
node src/pipeline/collect.ts --selftest
node src/pipeline/collect.ts --source <소스명> --pages 1 --dry-run   # DB 없이 건수만
node src/pipeline/collect.ts --source <소스명> --pages 1              # 실제 적재
```

`--dry-run` 출력의 **`⚠ 학력 미판정`** 목록을 반드시 확인한다. 비어 있지 않으면
`EDU_LEVELS` 에 추가한 뒤 다시 돌린다.

적재 후 `data-quality` 에이전트를 돌려 판정 분포와 날짜 파싱 실패율을 확인한다.

## 7. 문서 갱신

- `README.md` — API 표에 소스 추가, "알려진 미검증 지점"에서 해당 항목 제거
- `CLAUDE.md` 6절 — 검증 상태를 ⚠️ 에서 ✅ 로
- Notion 계획서 — 마일스톤 체크박스

## 흔한 실패

| 증상 | 원인 |
| --- | --- |
| 수집은 되는데 `hs_ok` 가 전부 false | 학력 필드명이 틀렸거나 문자열이 `EDU_LEVELS` 에 없음 |
| `closes_at` 이 전부 null | 날짜 형식 미지원 → 검색 쿼리가 모든 공고를 걸러냄 |
| 0건 수집 | 페이지 번호가 0-based 인지 1-based 인지 확인 |
| UPSERT 0건 | `source_id` 나 `url` 이 비어 있음 (`upsert` 가 걸러낸다) |
